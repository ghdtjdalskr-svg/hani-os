## 1. 쉬운 요약 (회장님용)

지금 본사 직원들은 **"무슨 말을 할지"와 "어디에 서 있을지"를 서로 따로 정하고 있어요.** 그래서 말과 위치가 어긋나요. 그리고 복도의 여러 지점이 그림 위에서는 **한 점에 겹쳐 그려져 있어서**, 걸어가는 시간 동안 복도 한가운데에 멈춰 서 있는 것처럼 보여요. 자리로 돌아올 때는 **다른 직원 바로 옆(그림 기준 몇 픽셀)을 스쳐 지나가는데**, 지금 검사는 "완전히 같은 점"만 막아서 이걸 못 잡아요.

새 설계는 한 문장으로:
> **직원 한 명 = 상태 하나.** "자리에 있음 → ○○ 가는 중 → ○○에서 하는 중 → 자리로 돌아가는 중" 순서로만 움직이고, 화면에 보이는 문구는 그 상태에서만 나온다. 장소와 좌석은 장부 하나에 예약한다.

## 3. 새 설계

### 3-1. 장소 카드 (Place Registry) — "그 층에 장소가 없으면 그 행동은 없다"

`data/hani-building/office-places.json` (새 데이터 파일, 런타임 읽기 전용)에 장소를 카드로 등록한다.

```json
{ "id": "pantry-2f", "floor": "2f", "room": "pantry", "kind": "coffee",
  "slots": ["pantry_2f", "finance-lounge-a", "finance-lounge-b"],
  "go": "팬트리로 커피 내리러 가는 중",
  "at": ["팬트리에서 커피 내리는 중", "팬트리에서 간식 고르는 중"],
  "pose": "stand", "stay": [8, 14] }
```

- 장소 종류(kind): `coffee`, `window`, `sofa`, `meeting`, `board`, `server`, `plant`, `lobby`.
- **행동은 장소 종류를 요구한다.** "커피" 행동은 `kind: coffee` 카드가 같은 층에 있고 빈 슬롯이 있을 때만 고른다. 3층엔 커피 카드가 없으니 3층에서는 커피 행동이 나오지 않는다.
- **책상 딴짓 문구에는 장소 단어를 쓰지 않는다**("창밖", "화이트보드", "소파", "팬트리" 금지 — 테스트로 강제).
- 창가(`window`): 지금은 창가 지점이 없다. **새 창가 슬롯을 아트 그림 위 실제 창 앞에 추가**한다(층마다 1–2개, 아린 리뷰 + 화면 확인). 슬롯이 생기기 전까지 창가 행동은 꺼 둔다.

### 3-2. 직원 상태기계 — 하나만

```
AT_HOME ──출발──▶ GOING(장소) ──도착──▶ AT_PLACE ──끝──▶ RETURNING ──도착──▶ AT_HOME
                     │                                     │
                     └──── 길이 막히면 WAITING(안전 대기점) ◀┘
```

| 상태 | 위치 | 화면 문구 |
|---|---|---|
| AT_HOME | 자기 `homeAnchor` | 업무/책상 딴짓 문구 (장소 단어 없음) |
| GOING | 예약한 경로 위 | `카드.go` ("팬트리로 커피 내리러 가는 중") |
| AT_PLACE | 예약한 슬롯 정확히 | `카드.at` 중 하나 ("팬트리에서 커피 내리는 중") |
| RETURNING | 자기 homeAnchor로 가는 경로 | "자리로 돌아가는 중" |
| WAITING | 검증된 대기점 | "잠깐 기다리는 중" |

- 문구는 **상태에서만** 만든다. 위치와 문구를 따로 추첨하는 코드는 지운다.
- 정식 예약 행동(216/221 카탈로그)도 같은 상태기계를 쓴다. 이미 `performStart/performEnd`로 이동과 수행을 나누고 있으니, "이동 중" 문구만 `○○ 가는 중`으로 바꾼다.
- RETURNING의 목적지는 언제나 `canon.people[].homeAnchor`(밤 라운지 근무자는 그 시간대의 근무 자리).

### 3-3. 예약 장부 하나 (Reservation Ledger)

- 산책·정식 행동·방문객이 **모두 같은 `plan()` 장부**를 쓴다. 지금처럼 순수 함수(날짜+시각 → 같은 결과)이고, 저장소/Cloud에는 아무것도 쓰지 않는다.
- 좌석: 사람별 homeAnchor는 **영구 예약**(본인만). 장소 슬롯은 시간 구간 예약 — 같은 시각에 한 슬롯엔 한 명.
- 경로: 문·좁은 통로는 시간 구간 예약(지금의 FIFO 유지). 산책도 여기에 들어간다.
- 사후 "그 순간만 집으로 돌리기"(`:504–509`)는 **삭제**. 겹칠 일은 예약 단계에서 아예 출발하지 않는다.

### 3-4. 화면 좌표 정리 (Art-map)

- 각 층 `hall_*` 지점에 **서로 다른 아트 좌표**를 준다(각 방 문 앞 복도). 결과: 0px 보행 구간 0개.
- 이동 시간은 **화면 거리** 기준으로 계산(논리 좌표와 그림이 달라도 "걷는데 안 움직임"이 없게).
- 경로 안전거리: 모든 보행 구간은 다른 사람 homeAnchor에서 **최소 거리(시작값 24px @1672폭)** 이상 떨어져야 한다. 못 지키는 경로(`path_client_booth_slot_1_22` 등)는 지점을 옮기거나 그 경로를 쓰지 않는다.
- 정지한 두 사람은 같은 층에서 최소 20px 이상(시작값, 390폭 실제 스프라이트로 최종 확정).

### 3-5. 그대로 지키는 것

- `window.HaniBuildingScene`의 `floors`, `canon.people[].homeAnchor/status`, `art.anchors[id].x/y`, `anchors`(Map).get(id).floor — 책상 마스코트(서윤, 2.9.231)가 읽음. **변경 없음.**

### 3-6. 지우는 것 (덧붙이지 않고 정리)

- `idlePools.stroll`, `strollPlan()`/`idleStroll()`의 독립 문구 추첨 → 장소 카드 기반 상태기계로 대체.

- 3번 문제의 "그림상 겹쳐 보이는 정도"는 모델 좌표로 측정했다. 실제 픽셀 겹침은 낮 시간대 브라우저로 구현 단계에서 확인한다.
- 아트 좌표를 옮기면 문 통과·가구 가림·모바일 화면이 함께 바뀔 수 있어 화면 확인이 필요하다.
- 운영 증거는 로그인 화면을 제 탭에서만 잠시 가리고 찍었다(데이터·저장소 변경 없음).
