# 보호 저장 경로 검증 방식 변경 제안 · 승인 전

2026-10-05 · 성민 대표님 검토용

게이트 변경은 아직 구현하지 않았습니다. 최신 main v2.9.178의 보호 키 직접 쓰기는 9곳, 삭제는 3곳입니다. 원본 보호 후보는 모든 경로를 잠금 검사 함수로 모아 직접 쓰기 2곳·삭제 1곳으로 줄였습니다. Cloud hani_state 호출은 양쪽 모두 5곳이며 query/schema를 바꾸지 않았습니다.

기존 서버의 PROTECTED_WRITE_SURFACE는 호출 개수가 다르면 무조건 차단합니다. 따라서 기능 검사가 통과해도 현재 후보를 배포할 수 없습니다. 로컬 Pre-QA도 저장 변경과 보호 키 변경을 검토 대상으로 유지합니다.

제안은 개수 검사를 없애거나 특정 후보를 무조건 통과시키는 방식이 아닙니다. 기본 판정은 그대로 두고, 별도로 승인받은 보호 저장 계약에만 다음 강화 검증을 적용하는 것입니다.

1. 승인 계약의 기준 main SHA·후보 SHA·저장 경로 파일 hash를 고정합니다. 다른 수정은 승인 재사용 불가입니다.
2. 보호 키 이름·내부 데이터 버전 불변, 허용된 쓰기/삭제 함수의 모든 실제 호출 경로, Cloud revision 조건을 검증합니다. 경로 추가·우회·원본 clear는 차단합니다.
3. 손상 원본 잠금, 사본 재읽기, 검증된 복원, 취소·공간 부족·읽기 오류·재읽기 불일치·롤백·다른 탭의 복원 보류에 대한 실제 실행 증거를 필수로 묶습니다.
4. 부정 검사로 잠금 제거·원본 키 변경·재읽기/rollback 제거·Cloud 조건 제거·승인 SHA 변경을 넣었을 때 반드시 차단하는지 확인합니다.
5. 독립 HINA 검토와 대표 승인, package 무결성, Pages/read-back 조건은 유지합니다. 게이트 변경 자체의 운영 반영도 별도 최종 승인 대상입니다.

현재 승인 요청 범위는 **이 판정 방식의 개발·검증**입니다. main 병합·서버/사이트 운영 배포 승인을 포함하지 않습니다. 안전 계약 검사 구현 중 부족함이 발견되면 기존 차단을 유지합니다.

근거: 성민 대표님의 현재 개발 효율 지침은 “not authorization to deploy or weaken a gate”이며 “Existing enforced gates remain mandatory; do not bypass them”이라고 명시합니다. 기존 구현 진행 승인은 이 새 게이트 변경까지 자동으로 확대하지 않습니다.
