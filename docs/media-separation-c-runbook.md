# 표지·포스터 C단계 실행 순서

작성: 도연(Codex), 2026-10-20 KST. 조사 기준 `3919a257` / v2.9.221.
이 문서는 실행 준비용입니다. 이번 개발에서는 실제 생활 데이터에 C단계나 복구를 실행하지 않았습니다.
성민 대표님은 C단계를 승인했고 Supabase 요금제는 올리지 않기로 결정했습니다.
**2026-11-09 이후에도 날짜만 보고 실행하지 않습니다. Cloud가 실제로 돌아온 것을 먼저 확인합니다.**

## 시작하기 전에

- PC 한 대를 실행 기기로 정합니다. 작업 중 PC·휴대폰·다른 탭에서 기록을 추가하거나 수정하지 않습니다. 다른 기기는 완료 후 받기만 합니다.
- 같은 소유 계정으로 Cloud 로그인·동기화 ON, 정상 조회와 최신 revision 수신을 확인합니다. quota·네트워크 오류, 복구/가져오기 대기, Local/Cloud 충돌이 있으면 중단합니다.
- **모든 PC·휴대폰과 열린 탭을 v2.9.221 이상으로 새로고침**합니다. 각 기기의 표시 버전과 책·영화 목록을 직접 확인하고, 오래된 탭은 닫습니다. 화면의 예전 v2.9.201 안내보다 이 조건을 우선합니다.
- 설정 → 데이터 → JSON 백업 / 복원 → **백업 파일 만들기**로 이미지까지 재결합된 전체 JSON을 보관합니다. 별도 검증 환경에서 JSON 구문·기록 수·모든 이미지 본문과 digest를 검사합니다. 운영 앱에 시험 복원하지 않습니다. 참조만 있는 파일이나 이미지 누락 파일이면 중단합니다.
- 설정 → 데이터 → Google Drive 백업 보관함에서 **백업 폴더 연결**로 PC Google Drive 내 폴더를 선택한 뒤 **사진 백업**을 누릅니다. `HANI_OS_photos/manifest.json`과 실제 사진 파일을 확인합니다. **누락 0건**이어야 합니다. 신규 0장은 이전 파일이 재검증됐다는 뜻일 수 있습니다. 이미지 없는 기록은 대상에서 제외되므로 현재 이미지/ref가 있는 모든 책·영화가 manifest의 records에 있는지도 대조합니다.
- Drive 데스크톱 앱에서 업로드 완료를 확인합니다. 가능하면 Drive 웹에서 manifest와 사진을 내려받아 해시까지 대조합니다. HANI의 로컬 파일 검증 성공만으로 원격 Drive 완료로 판단하지 않습니다.
- Cloud `hani_media`에서 현재 모든 coverRef/posterRef의 행을 **읽기만 하여** 확인합니다. 소유 계정, media_id, MIME, bytes, data 본문 digest가 일치해야 합니다. digest는 **data URL 문자열 UTF-8의 SHA-256**이며 사진 파일 바이트 SHA-256과 다릅니다. Drive manifest의 `records[].mediaRef`는 이 참조이고 `images[].digest`는 파일 바이트 해시입니다.
- B 운영 기록의 36개 이미지 / 중복 제외 33행은 과거 참고치입니다. 실행 당일 실제 기록을 기준으로 셉니다. 새 이미지에 참조가 없다면 C를 진행하지 말고 B단계 보관 상태부터 점검합니다.
- 실행 전 기록 크기와 이미지/ref 수를 남깁니다. 설정의 저장 용량 표시와 함께 읽기 전용 개발 도구에서 `new TextEncoder().encode(localStorage.getItem('hani_os_life_v23')).length`로 UTF-8 bytes를 기록할 수 있습니다. 저장소 편집 기능은 사용하지 않습니다. 전체 JSON 백업 파일과 Drive 폴더를 삭제하지 않습니다.

## PC 한 기기에서 누르는 순서

1. 설정 → 데이터 → **표지·포스터 분리 미리보기**로 갑니다. 위 조건을 다시 확인합니다.
2. **C단계 · 내장 이미지 분리**를 한 번 누릅니다. 기기 사본과 Cloud 보관 목록 검사 후 확인창이 열립니다. 누락·불일치·동기화 오류가 보이면 멈춥니다.
3. 확인창의 **모든 기기와 열린 탭을 새로고침했습니다**를 실제 확인한 뒤 체크합니다. **C단계 실행**을 한 번 누릅니다. 취소 또는 ESC는 실행하지 않습니다.
4. 전체 안전 백업 생성·재읽기, Cloud 본문 digest 검사, 기존 저장 경로 처리가 끝날 때까지 기다립니다. 탭을 닫거나 다른 기기에서 수정하지 않습니다.
5. 결과 `C단계 · N장 저장 · digest 불일치 0건 보존`을 기록합니다. N과 실행 전 분리 대상 수를 대조합니다. 충돌/중단이면 완료로 표시하지 않습니다. 자동 재실행하지 말고 원인을 확인합니다.
6. PC의 기존 Cloud 동기화가 끝나고 최신 revision이 저장·재조회된 것을 확인합니다. 버튼의 로컬 저장 완료만으로 기기 동기화 완료를 판단하지 않습니다.

## 실행 후 확인

- 같은 방법으로 state bytes를 다시 측정하고 전/후 수치를 남깁니다. 약 2.16MB → 약 0.3MB는 과거 예상치이며 성공 기준 수치가 아닙니다.
- 모든 대상 책/영화에서 빈 cover/poster와 유지된 coverRef/posterRef를 확인합니다. id·제목·기록 수·다른 생활 데이터는 같아야 합니다. 미분리 inline이 있다면 원인을 기록합니다.
- PC를 새로고침한 뒤 서재와 시청 아카이브에서 **대상 이미지 전부**가 참조로 표시되는지 확인합니다. 몇 장만 보고 통과시키지 않습니다.
- 휴대폰은 수정 없이 최신 Cloud를 받습니다. 버전·revision 확인 후 서재와 시청 아카이브의 같은 이미지 전부를 확인합니다. 새로고침 뒤에도 보여야 합니다. PC/폰의 이미지 수와 누락 0을 기록합니다.
- PC에서 **백업 파일 만들기**를 다시 실행합니다. 내보낸 파일에서 ref 이미지 전부가 data URL로 재결합되고 digest·기록 수가 맞는지 검사합니다. 내부 state는 계속 ref 형태여야 합니다. `사진 백업`도 다시 실행해 누락 0 및 파일 재검증을 확인합니다.
- 확인 기록에는 날짜(KST), 각 기기 버전, 실행 전/후 bytes, 대상/분리/충돌/누락 수, Cloud revision, 전체 백업 파일명, manifest 검증 결과를 남깁니다. 비밀정보와 생활 원본은 개발 게시판에 붙이지 않습니다.

## 되돌리기: 다시 내장

1. 이미지가 안 보이거나 동기화 결과가 다르면 다른 기기 편집을 멈춥니다. 앱 데이터·IndexedDB·Cloud 행·사진 폴더를 지우거나 초기화하지 않습니다. 전체 JSON과 Drive 사본을 유지합니다.
2. 실행 PC의 소유 계정·Cloud 연결·동기화 idle 상태를 확인합니다. 설정 → 데이터 → 표지·포스터 분리 미리보기 → **표지·포스터 다시 내장**을 누릅니다.
3. 확인창에서 **다시 내장 실행**을 누릅니다. 도구는 전체 안전 백업을 먼저 확인하고 비어 있는 inline만 검증된 IndexedDB/Cloud 본문으로 채웁니다. 기존 inline, ref, 최소 쓰기 버전은 유지합니다.
4. `다시 내장 · N장 저장`을 확인하고 PC 전체 이미지·state bytes·재결합 백업·Cloud revision·휴대폰 수신을 다시 확인합니다.
5. Cloud가 다시 내려갔거나 원본 이미지가 양쪽 모두 없으면 이 UI도 실행이 막힐 수 있습니다. 도구로 복구할 수 없으면 멈추고 보관한 **전체 JSON을 기존 복원 절차로 검증한 뒤** 담당자와 복구합니다. manifest 사진만으로 생활 데이터 전체를 복원할 수는 없습니다. 보호 키를 직접 수정하거나 오래된 Cloud를 덮어쓰지 않습니다.

## 코드 조사에서 확인한 빈틈과 수동 보완

- `hani-main.js`의 `mediaRunC`, `mediaCConfirm`, `mediaCBlockedReason` 및 `hani-media-core.js`의 `verifyRefs`, `prepareC`를 확인했습니다. C·복구 로직은 이번에 바꾸지 않았습니다.
- 실행창은 v2.9.201 이상을 안내하며 모든 기기의 실제 버전/열린 탭을 자동 검증하지 않습니다. 체크박스는 사용자 확인입니다. 이번 실행 기준은 수동으로 **모두 ≥2.9.221**입니다.
- C는 Drive 사진 백업 여부·누락 0·원격 업로드 완료를 검사하지 않습니다. 위 사전조건을 별도로 확인해야 합니다.
- 버튼을 누를 때의 첫 검사는 IDB 및 Cloud **목록** 검사입니다. 확인 후 `prepareC`가 모든 참조의 Cloud **본문**까지 검증합니다. 목록 확인창만으로 본문 검증 완료라 판단하지 않습니다.
- ref가 없는 inline은 C 대상이 아니고, inline/ref 불일치는 보존합니다. 검사 대상 누락을 막으려면 실행 전 전체 이미지 목록과 B 참조를 대조해야 합니다.
- 확인창 이후 idle 대기 중 state 객체가 교체되면 runner가 최신 state를 다시 기준으로 잡을 수 있습니다. 미리 만든 Drive/전체 백업과 최종 state가 다를 수 있으므로 실행 중 편집을 금지하고, 변경이 발견되면 취소 후 백업부터 다시 확인합니다.
- 기존 `save()` 성공 뒤의 Cloud 전송·다른 기기 이미지 표시·완전 export는 별도 확인 항목입니다. 도구는 이를 모두 완료했다고 보증하지 않습니다.
- 다시 내장도 현재 UI에서는 Cloud 로그인·온라인/idle 조건이 필요합니다. IndexedDB에 사본이 있어도 Cloud 장애 중 실행 가능한 복구 버튼이라고 안내하면 안 됩니다.
