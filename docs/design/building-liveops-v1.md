## 0. 회장님용 쉬운 요약 (5줄)

1. **지금 있는 재미를 한눈에 정리했습니다**: 매일 쌓이는 친밀도·출석·사내 드라마, 매주 나오는 하니 일보·시황 4컷·미룬 일 치비툰, 매월 돌아오는 이달의 퀸·이달의 직원까지 이미 훌륭한 뼈대가 있고, 여기에 `2.9.310` 예정인 **출석 도장판(`hani_attendance_v1`)**이 곧 합류합니다.
2. **건물 대공사(1F 편의점·5F 라이프·6F 옥상·RPG)와 연결되는 장기 콘텐츠 10가지를 설계했습니다**: 회사 성장 레벨, 희귀 장면 도감, 직원 성장 이야기, 월간 객원 NPC, 계절 테마(THAW 등), 주간 갓생 사내 미션, 편의점·카페 순환 신메뉴, 스튜디오 방송 시즌, 부서 대항전, 기념일·생일 주간까지 모두 **"데이터 파일만 추가하면 계속 업데이트"**되는 구조입니다.
3. **'생활 기록 앱'의 본질(갓생)을 절대 해치지 않습니다**: 게임 숙제 때문에 피곤해지지 않도록 놓쳐도 불이익이 없고, 오히려 걸음·독서·공부·가계부 같은 **실제 생활 기록을 남기면 회사에 즐거운 보상**이 열리도록 연결했습니다.
4. **핵심 데이터(`hani_os_life_v23`)는 단 1바이트도 건드리지 않습니다**: 무저장·읽기 전용으로 즐길 수 있는 장치와 별도 로컬 키가 필요한 기능을 명확히 분리했고, 저장이 필요한 신규 기능은 **전부 '★ 회장님 승인 필요'**로 표시했습니다.
5. **1차는 가볍고 즉시 재미있는 3종(주간 갓생 미션·계절/편의점 순환·희귀 장면 도감)부터** 대공사 Phase 2~4에 맞춰 얹고, 회사 레벨·부서 대항전은 2차로 확장하는 로드맵과 **12월~2월 3개월 운영 달력**까지 준비했습니다.

## 5. 위험 분석 및 방어 장치 (Risk Register)

장기 운영 콘텐츠를 잘못 설계하면 오히려 앱이 무거워지거나 생활 기록 앱의 본질을 해칠 수 있습니다. 아래 5가지 핵심 위험을 사전에 차단합니다.

| 위험 항목 | 구체적 문제 시나리오 | 방어 및 완화 장치 (Design Guard) |
| --- | --- | --- |
| **1. 저장 키 남발 & 데이터 안전 위협** | 콘텐츠마다 새 `localStorage` 키를 7~8개씩 만들면 ① 브라우저 저장소 파편화, ② 기기 교체 시 유실, ③ 실수로 `hani_os_life_v23`을 건드리는 사고 발생 위험. | ① **무저장 파생(Projection) 최우선**: `state`, `hani_office_affinity_v1`, KST 날짜에서 계산할 수 있는 것은 절대 별도 저장하지 않음.<br>② 영구 저장이 꼭 필요한 경우에도 **단일 통합 키 최대 1~2개**(`hani_office_codex_v1` / `hani_building_progress_v1`)로 제한하고 `5KB` 이내 유지.<br>③ 모든 신규 키는 **★ 회장님 사전 승인** 및 `denyWrite(hani_os_life_v23)` 테스트 필수. |
| **2. 보상 인플레 (금방 다 깨고 질림)** | 초반 1~2주 만에 도감·레벨·친밀도 비밀을 전부 해금해 버리면 그다음부터 업데이트 전까지 할 거리가 사라짐. | ① **속도 제한 장치**: 친밀도 하루 2점 상한 유지, 희귀 장면 하루 최대 1~2건 + `3~7일` 쿨다운.<br>② **계단식 호흡**: 초반 해금(Lv1~3, MBTI)은 경쾌하게 주고, 장기 보상(Lv5+, 12종 도감, 연간 기념일)은 수주~수개월 호흡으로 배치.<br>③ **순환 소비형 재미** 병행: 주간 미션, 편의점 1+1, 월간 퀸은 매주/매월 리셋되므로 끝이 없음. |
| **3. '숙제'처럼 느껴지는 부담감** | 연속 출석(스트릭)이 끊기거나 주간 미션을 못 채웠을 때 실패감·죄책감이 들면 오히려 갓생 앱을 켜기 싫어짐. | ① **놓쳐도 괜찮은 설계(No Penalty)**: 연속 출석이 끊겨도 기존 도장/경험치 **차감 0**, "어제 바빴나 봐요, 오늘부터 다시!" 같은 따뜻한 대사만 출력.<br>② **느슨한 주간 커트라인**: 7일 매일 강제가 아니라 "주 3일 기록" 또는 "4개 중 2~3개" 달성으로 충분.<br>③ **지나간 콘텐츠 보존**: 못 본 일보·4컷·생일 엽서는 보관함에서 언제든 다시 열람 가능. |
| **4. 데이터 손실 시 박탈감 & 백업 범위** | 브라우저 캐시 초기화나 기기 변경 시 로컬에만 저장된 도감·출석 도장이 날아가면 박탈감이 큼. | ① **핵심-보조 분리 원칙**: 회장님의 진짜 소중한 자산(`hani_os_life_v23`: 투자·가계부·독서·일기·건강)은 Cloud + JSON 백업이 완벽 보호하며, 오피스 수집 요소는 **잃더라도 본체 기록에 영향 없는 가벼운 재미**로만 유지.<br>② 별도 로컬 키 승인 시, 기존 **빠른 백업(`#quickBackup` JSON 내보내기)의 읽기 전용 선택 포함/복원** 지원 여부를 아키텍처 단계(서윤 리드)에서 함께 검토 (Cloud 스키마 변경 없이 로컬 파일 백업만 보조). |
| **5. Closure 200파일 상한 & 390px 성능 저하** | 매달 새 그림과 JSON을 마구 추가하면 `one-pass-gate-contract.json`의 `200파일 / 25MB` 상한을 넘거나 모바일 100ms 틱(`400ms` 한도)이 느려짐. | ① **콘텐츠 = JSON 데이터 행 추가 + 기존 스프라이트/통합 시트 재사용** 원칙 철저 준수.<br>② 매주 발행하는 일보/4컷 외의 Live-Ops 모듈은 `assets/data/*.json` **기능별 통합 파일 1개씩**으로 묶고, 100ms 틱에서는 `activeFloor`와 오늘 날짜(`KST`)에 해당하는 slice 1건만 참조. |
