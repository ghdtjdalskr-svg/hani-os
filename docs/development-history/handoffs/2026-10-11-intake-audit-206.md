## 결과와 증거

### 정확한 실행 경로

1. `index.html`의 `hani-main.js → hani-ui-v02992.js → hani-yuna-helpdesk.js` 순서. main의 `intakeInit`이 구 Intake DOM에 이벤트를 연결한 뒤 helpdesk `init/render`가 #intake를 교체. 구 `#intakeAnalyzeBtn/#intakeCommitBtn`은 실제 인포데스크 전송 경로가 아님. 공통 hero/care는 보존하고 desk/composer/conversation은 최초 1회 생성해 유지.
2. 칩/분류 → `chooseCategory` → `model.category`. 다른 칩을 선택하면 미완성 이전 draft·수정·재시도만 해제하여 이전 종류의 누락 질문으로 새 메시지를 흡수하지 않음. 생활 state는 변경하지 않음.
3. 버튼 → `scheduleSend → submitText`. Enter는 Shift·조합 상태·keyCode 229·compositionend 직후 Enter를 제외하고 동일한 `scheduleSend`를 사용. `compositionstart/end`는 조합 상태를 관리. 조합 중 버튼을 누르면 blur로 조합 확정 → compositionend → 다음 task에서 최종 input.value 읽기. 중복 예약/분석 중 재전송 차단.
4. `submitText`: 사용자 말풍선 push → 대화 DOM 반영 → input 비움 → 유나 “확인 중…” 말풍선/분석 상태 즉시 반영. 40ms 뒤 실제 처리. 이 순서를 Node 및 실제 DOM mutation 이력으로 확인. 정상 텍스트는 AI/Cloud를 호출하지 않음.
5. `processText → routeIntent / hydrateMissing / editDraft / parse(text,category)`. 책은 기존 main의 `intakeNaturalBook`을 재사용. 시청·할 일·장소·일기는 helpdesk 로컬 파서. 누락 값 질문 → 다음 사용자 답변 → Preview 카드. 금융·정밀 운동은 전문 탭으로 이동하며 자동 저장하지 않음. 일정 Preview는 저장 미지원이라는 기존 경계를 유지.
6. 사진은 `bounded(analyzeImage,15000)` 안에서 `intakeImageToDataUrl → agentApi('extract_intake_image') → cloudRequire/session(getSession) → fetch hani-agent-orchestrator → JSON/ok 검증 → visionDraft → 질문 또는 Preview`. 디코딩·세션·네트워크·응답 파싱 전체를 시간 제한으로 감쌈. 오류 시 파일/원래 draft/칩/요청을 보존하고 오류 말풍선+다시 시도. 재시도는 사용자 말풍선을 중복 추가하지 않음. 새 접수 후 늦은 완료는 operation identity가 달라 무시.
7. Preview의 `#yunaSave` 클릭만 `saveApproved → saveData → intakeBlockerInfo/intakeDuplicateInfo → intakeApplyRow → commit → save → writeProtectedState → 기존 키 read-back → 기존 cloudQueueSync`. 성공 시 draft를 해제하고 **같은 대화 아래** 성공 말풍선 추가. 실패 시 기존 state rollback, 오류 말풍선/명시 재시도. 중복/차단은 무저장 안내 말풍선.
8. `scrollLatest`는 진행·완료·저장·오류·viewport 변화 시 내부 conversation을 최신 위치로 이동. `adjustViewport`는 visualViewport와 실제 #intake 상단 위치로 사용 가능 높이를 계산. 입력창 위치와 대화 높이를 같이 보정해 키보드에 가려지는 답변을 방지.
9. `새 접수 → clearAll → invalidateSend`: 분석 identity/예약/조합 상태 무효화, 메시지·draft·칩·입력·첨부 초기화. 기존 생활 기록은 유지. 같은 sessionStorage 초안 경로만 사용. 복원 시 “계속하기” 전에는 composer를 비활성화하며 과거 분석 중 status로 영구 차단되지 않음.

### Cloud/AI 서버 감사

- Supabase `get_edge_function`으로 실제 `hani-agent-orchestrator` ACTIVE/version54 소스 읽기 성공. 배포·수정·함수 호출은 하지 않음. 서버 bundle ezbr SHA `adc8409f8d0e124e44aeac85e2f3ae1f4117bffb7a660d639dec242ea24dd91f`(도구 metadata 원문).
- gateway verify_jwt=false이지만 함수 진입에서 Bearer와 `auth.getUser()`로 직접 인증 확인 후 action 분기. 인증 실패401, 서버 환경/API 설정 실패500, 이미지 검증400/413, OpenAI/빈 응답/JSON 파싱 실패502 반환.
- `extractIntakeImage`는 OpenAI Responses JSON schema 추출, `extractIntakeText`는 주로 wishlist용. 두 action branch에 DB/state 쓰기 없음(`db_write:false`, `hani_state_touched:false`). 실제 인증/요금/키 값은 기록하지 않음.
- 서버 auth 및 OpenAI fetch에도 자체 timeout이 없음. 이번 UI boundary가 이를 15초 뒤 오류/재시도로 표시하지만 **원래 네트워크 요청을 abort하지는 않음**. reset/timeout 뒤 완료는 데이터/대화에 적용하지 않음. 사진 AI가 15초보다 느리면 실패 안내가 나올 수 있음. 서버 개선은 별도 담당 범위.
- active helpdesk는 `extract_intake_text`를 호출하지 않음. main legacy `intakeAnalyze`의 wishlist/이미지 경로만 해당 호출을 사용하고 구 UI DOM은 helpdesk가 교체함. legacy standalone intake 분석의 별도 timeout/alert UX는 이번 수정 범위 아님.
- [Supabase getSession 공식 문서](https://supabase.com/docs/reference/javascript/auth-getsession) 확인. changelog markdown fetch는 도구 content-type 미지원으로 확인 실패. SDK/auth 구현 자체 변경 없음.
