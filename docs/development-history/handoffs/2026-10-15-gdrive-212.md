## Google Cloud Console 설정 (배포 담당 / 성민 대표님)

1. [Google Cloud Console](https://console.cloud.google.com/)에서 **현재 Calendar의 서버 GOOGLE_CLIENT_ID가 속한 동일 프로젝트**를 선택한다. 새 프로젝트/새 OAuth client를 만들지 않는다. client ID와 비밀값은 문서·로그·스크린샷에 복사하지 않는다.

3. **Google Auth platform → Data Access → Add or remove scopes**(이전 UI: APIs & Services → OAuth consent screen → Edit app → Scopes)로 이동한다. `https://www.googleapis.com/auth/drive.readonly`를 선택/직접 추가하고 **Update → Save**. 기존 `https://www.googleapis.com/auth/calendar.events`도 유지한다. drive.file 등 다른 scope로 대체하지 않는다.
4. **Google Auth platform → Audience → Test users → Add users**에서 실제 소유자 Google 계정 이메일을 추가하고 저장한다(Testing/External인 경우). HANI 서버 `HANI_OWNER_USER_ID`는 Supabase 소유 사용자 ID이고 Test user는 Google 이메일이므로 혼동하지 않는다. Calendar와 같은 Google 계정으로 동의한다.
5. **Google Auth platform → Clients → 기존 Calendar Web application client → Authorized redirect URIs**에서 `https://qmgikfdwjzmhkwadycxk.supabase.co/functions/v1/hani-google-calendar/callback`이 기존 등록값과 일치하는지 확인한다. Drive callback URL을 새로 등록하지 않는다. 기존 app origin과 callback 공개 접근 설정은 바꾸지 않는다.
6. 테스트 단계는 기존 Publishing/Testing 상태를 유지한다. 공개 게시·Google scope verification·조직 정책 변경이 필요하면 별도 승인을 받는다. 이번 작업은 Console 변경을 실제 수행하지 않았다.
