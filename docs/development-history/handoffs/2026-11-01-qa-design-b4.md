### 코드 확인과 변경

1. **홈 안전 경고·조치 카드 (HIGH, 확인)**: 닫힌 `details#homeNews` 안의 storage notice, 월말 chip, 정산 카드, care 카드가 숨겨지는 구조 확인. 기존 정산 DOM을 새 정적 `#homeActions`로 이동하고 notice/chip/care의 기존 owner가 이 슬롯에 생성·갱신하게 함. 슬롯은 소식 위에 계속 존재하고 모든 자식이 hidden이면 CSS로 공간까지 제거. 소식에는 일보·마일스톤만 남기며 직접 보이는 자식만 건수에 포함. 기존 care/정산/notice 버튼 owner와 일보·마일스톤 파일은 변경하지 않음.
2. **체중 방향·활성 기간 (HIGH, 확인)**: 기존의 `delta / (target-start)`만으로는 시작=목표, 적용 전 기록, 이미 목표를 지난 시작값을 분류할 수 없었음. 현재 승인 목표의 이전 승인 지표 이력과 적용일 이전 측정 근거를 우선 사용하고, 적용일 기준점이 없을 때 목표 쪽 실제 이동이 확인되는 경우만 방향을 추론. 적용 후 기록이 없거나 방향 근거가 없으면 시작/현재/목표/변화 값만 표시하고 퍼센트 생략. `away`이면 항상 0%, `reached`와 `away` 동시 표시 금지. 예시 10/01 70→10/15 69(목표70, 방향 근거 없음)는 퍼센트·달성·away 생략. 09/25 68→10/15 67(목표70, 방향 근거 없음)도 증량으로 단정하지 않음. 이전 승인 목표80→70 또는 실제 80→70→69 이력이 있으면 감량 달성100%, away false.
3. **걸음 달력 (MEDIUM, 확인)**: month/year가 빈 날짜 배열을 만들기 때문에 빈 상태 조건에 걸리지 않던 문제 확인. 렌더러가 실제 기록 존재를 확인하게 하여 빈 월·빈 연도·전체에 안내를 표시. 실제 0보는 기록으로 유지. 기본 `asOf`를 `careKoreaPeriod().day`로 변경. 날짜 중복은 기존 `monthlyReportDaily` helper 재사용.
4. **동일 날짜 체중 (LOW, 확인)**: 날짜 정렬 후 배열 마지막 값만 선택하던 문제 확인. 체중도 유효한 체중 행을 기존 `monthlyReportDaily`에 전달해 최신 `updatedAt || createdAt` 우선, 동률은 마지막 저장 행 규칙 적용. 원본 배열·저장소 수정 없음.
5. **갱신 누락 (MEDIUM, 일부 확인)**: curriculum import 완료와 monthly report generate의 finally에서 기존 `renderHaniCareHome`을 호출. 정산 렌더를 이 owner에 모아 import·보고서 생성·홈 진입에서 함께 갱신하고 renderHome의 중복 정산 호출은 제거. 기존 news count 갱신도 같은 경로에 유지.

### 기각하거나 한정한 검토 내용

- **`showView("home")`에 care refresh 자체가 없다는 해석은 기각**: 원래부터 `['home','intake','tasks']`에서 `renderHaniCareHome()`을 호출함. `showView` 코드는 바이트 그대로 보존. 실제 빠진 정산 갱신만 기존 care owner 안에서 보완했고, 실제 showView 실행 테스트로 count·정산·닫힌 소식 상태를 확인.
- **Data Hub와 월간 보고서의 중복 동률 규칙이 완전히 같다는 전제는 기각**: generated Data Hub는 최신 시각 이후 id 역순을 사용하고 동일 시각·동일 id인데 내용이 다르면 ambiguous로 제외. standalone `data-hub/period-goal.mjs`도 동률 내용 충돌을 제외. 반면 월간 보고서 `monthlyReportDaily`는 동일/누락 시각에서 마지막 저장 행을 사용. 이번 투영은 기존 월간 보고서 helper를 직접 재사용했고 최신 시각이 다른 fixture는 실제 generated Data Hub와도 일치함을 실행 확인. **시각 동률의 기존 Data Hub/보고서 차이는 남아 있으며, 공통 집계 owner의 정책 변경은 하지 않음.** 이를 전체 수치 일치 PASS로 보고하지 않음.
- **체중 시작=목표이면 무조건100%라는 기존 기대값은 기각**: 방향을 모르면 퍼센트를 생략하라는 이번 요구에 따라 테스트 기대를 변경. 정확히 현재값=목표이면 실제 일치 달성만 표시할 수 있고, 방향 모르는 상태에서 목표를 벗어나면 달성을 추정하지 않음.
