## 결과와 증거

### Google OAuth 복귀

- `supabase/functions/hani-google-calendar/index.ts`: HTML 응답 helper와 콜백의 두 return만 변경. 성공은 302 `HANI_APP_ORIGIN`의 origin + `/hani-os/?google=connected`, 실패는 `?google=error&reason=access_denied|callback_failed`. 기본 origin은 `https://ghdtjdalskr-svg.github.io`. 본문은 비어 있고 `Cache-Control: no-store`; 토큰·state·raw 오류 메시지는 URL/본문/로그에 싣지 않음.
- state 검증·소모, 토큰 교환·암호화, 기존 연결 upsert, POST 인증·Calendar 동기화는 원본 바이트 그대로. 신규 DB write/schema/migration 없음.
- `hani-main.js`: 독립된 복귀 처리 블록과 기존 시작/로그인 해제 경로의 hook 2곳만 추가. 연결 완료/친절한 실패 toast, `google`·`reason` 제거, 다른 query·hash·history.state 보존. 로그인 전이면 메모리에서 대기하고 기존 로그인 게이트가 열린 뒤 `googleCalendarRefreshStatus()`와 `googleDriveLoad({status:true})`를 한 번 호출. 기존 Calendar/Drive 로직 바이트 보존.
- 앱 복귀 페이지를 보여주는 방식이며 새 popup 닫기/자동 로그인/기존 창 메시지 경로를 추가하지 않음. 실제 popup→앱 복귀와 세션 복구는 배포 후 검증 필요.
- 배포 담당이 **`supabase functions deploy hani-google-calendar --no-verify-jwt`**로 배포해야 함. OAuth GET callback에는 bearer JWT가 없으므로 `verify_jwt=false` 유지가 필수. 기존 POST의 서버 내부 사용자 검증은 유지. 이 작업에서는 배포하지 않음.
- 근거: [Supabase HTML 응답 제약](https://supabase.com/docs/guides/functions/http-methods), [redirect 응답](https://supabase.com/docs/guides/functions/status-codes). changelog markdown 직접 fetch는 content-type 오류였고 공식 changelog/문서 검색으로 대체. 이 수정은 API/스키마 변경 없음.

### 시장 일봉 지연 갱신

- `market-gateway/cache-publisher.mjs`: `onlyMissingCharts`는 이제 누락 차트 + 오래된 기존 일봉을 수집. 마지막 유효 candle의 KST 날짜와 최신 평일을 비교해 **평일 차이가 1일을 초과**할 때 갱신. 주말은 제외, 하루 휴장/아직 끝나지 않은 거래일은 1일 여유로 허용.
- 자동 실행은 누락 `1M`을 채우면서 기존 `1W/1M/3M/6M/1Y` 참조도 점검. 기존 intraday `1D`는 이 일봉 규칙으로 자동 갱신하지 않음. 새 기간을 전부 seed하지 않음.
- 자동/seed 경로의 공급자 chart 호출은 **실행당 기본 6개**. `maxChartsPerRun`은 1~25 정수만 허용. 누락과 stale이 같은 상한을 공유하며, 메모리상 최근 시도 순서로 회전해 휴장 등으로 값이 그대로인 앞 종목이 뒤 종목을 계속 막지 않음. 명시적 `--refresh-charts`의 기존 전체 기간/OHLC 검사 경로는 유지.
- 거래소 휴일 캘린더는 추가하지 않음. 여러 평일의 연휴에는 갱신을 시도할 수 있지만 공급자가 준 candle만 사용하고 동일 데이터는 동일 hash로 재사용. candle 합성/날짜 연장 없음.
- `market-gateway/pc-collector.mjs`: 기존 private chart 객체를 인증 GET으로 읽고 크기·SHA-256을 확인한 뒤 마지막 candle을 판단. 검증된 immutable ref의 날짜는 프로세스 메모리에 재사용. 별도 영속 metadata/key 없음.
- `market-gateway/portfolio-collector.mjs`: 기본 tick/watch에도 위 점검을 연결. 상한으로 아직 seed하지 못한 참조는 read-back에서 건너뛰고 다음 실행에서 채움. 기존 시세/객체 검증·5분 간격·인증·공급자 rate-limit/cooldown·페이지 제한 유지.
- 기존 JSON 형식, `charts/<sha256>.json`, `latest.json` pointer-last, 용량 제한 유지. 예전 immutable 객체 삭제 없음. 실패/차트 역행은 기존 최신 pointer를 보존. 기존 Storage 업로드 경로/권한 구조는 변경하지 않음.

- 저장소 `.github/workflows/`의 workflow 2개는 release/self-protect 검사이며 시장 수집 GitHub Action은 없음.

### 미검증 / 보존 / rollback

- 실제 브라우저 UI·popup OAuth·실제 Google 계정/Drive·Toss 응답·PC 작업 실행/설치본·운영 chart 최신일은 미검증. 합성 테스트 통과를 운영 해결 완료로 해석하지 않음.
- 로그인·기록 저장·Cloud 동기화의 전체 브라우저 안전/복구 검사는 실행하지 않음. 보호 경로 바이트 보존 및 위 관련 VM 회귀만 확인. release 담당이 기존 auth/rollback 안전 검사와 Preview/열차 gate를 수행해야 함.
- Candidate freeze/package/One-Pass/HINA/운영 배포/Production read-back 미실행. 기능 작업 지시에 따라 버전 증가 N/A(열차 담당이 한 번 증가). main merge·Pages·표시 버전/실제 JS 운영 로딩·기능 read-back 완료 아님.
- rollback은 승인된 코드/실행본으로 되돌리는 기존 배포 절차를 사용. DB/token schema는 동일, 예전 immutable chart는 삭제하지 않음. 운영 latest pointer/사용자 데이터의 자동 rollback·삭제는 구현하지 않음.
