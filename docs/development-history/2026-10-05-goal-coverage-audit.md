## 1. 현재 목표 등록이 다루는 범위

v2.9.178 목표 등록(`GOAL_METRICS`, `hani-main.js` 1206행)은 Data Hub 지표 6개만 다룹니다.

| 분야 | 지표 | 비고 |
|---|---|---|
| 투자 | 투자자산(원) | 월간 화면은 전월 비교만. 목표 달성률 미표시(정의서 G2) |
| 신체 | 체중(kg) | 동일(G2). 기존 1·2차 목표 체중은 별도 저장 |
| 문화 | 완독(권) | 동일(G2). 기존 연간·월간 독서 목표는 별도 저장 |
| 활동 | 일평균 걸음 | 0보와 미입력 구분 불가(`ZERO_STEPS_AMBIGUITY`) |
| 소비 | 월 지출 예산 | 가계부 월별 `targetT`와 중복 |

## 2. 목표가 없는 분야와 후보 지표

“데이터 준비도”는 코드상 필드 존재 여부만 판단합니다. 실제 기록이 충분히 쌓였는지는 확인하지 않았습니다.

### A. 데이터가 이미 있어 바로 지표화하기 쉬운 후보

| 분야 | 후보 지표 | 원본 | 집계 | 목표 의미 | 주의점 |
|---|---|---|---|---|---|
| 신체 | 체지방률(%) | `body[].fat` (`normalizeBodyRecord` 1101행) | 월 마지막 유효값 | `point_target` | 측정하지 않은 날은 빈 값 |
| 신체 | 골격근량(kg) | `body[].muscle` | 월 마지막 유효값 | `point_target` | 동일 |
| 활동 | 운동한 날 수 | `exercise[]` (3008행, 날짜당 1건) | 월 합계(일) | `cumulative_total` | “운동”의 정의(걸음만 입력한 날 포함 여부) 결정 필요 |
| 활동 | 이동 거리(km) | `exercise[].distance` | 월 합계 | `cumulative_total` | 0과 미입력 구분 불가(걸음과 같은 문제) |
| 문화 | 시청 편수 | `movies[]` `status=watched`, `watchedDate` | 월 합계 | `cumulative_total` | 시리즈 회차 묶음 기준을 월간 보고서와 맞춰야 함(현재 입력 1건 = 1건) |
| 기록 | 일기 쓴 날 수 | `diaries[].date` (3134행) | 월 합계(일) | `cumulative_total` | 같은 날 여러 편은 1일로 셈 |

### B. 데이터는 있지만 기간 규칙을 먼저 정해야 하는 후보

| 분야 | 후보 지표 | 원본 | 정해야 할 것 |
|---|---|---|---|
| 자격증 | 합격 개수(연간) | `certificates[]` `status=pass`, `resultDate` (1098행) | 연간 목표 전용으로 둘지. 결과일 없는 합격 기록 처리 |
| 여행 | 여행 횟수(연간) | `travelTrips[]` `startDate/endDate` (1096행) | 기간에 걸친 여행을 어느 분기에 셀지 |
| 투자 | 월 순입금(원) | `investmentCashFlows[]` deposit/withdrawal (2035행) | 계좌 간 이체 제외 규칙. 투자 성과와 저축 목표의 구분 |

### C. 지금 구조로는 목표화가 어려운 후보 (원본 보완 필요)

| 분야 | 후보 | 막히는 이유 |
|---|---|---|
| 할 일 | 완료율·완료 개수 | `tasks[]`에 완료 여부(`done`)만 확인되고 완료 시각을 찾지 못함 → 어느 기간에 완료했는지 알 수 없음 |

| 문화 | 평균 평점 | 목표로 삼기 부적절할 수 있음(감상 기록) |

## 3. 추천 순서 (제안)

1. **정의서 G2 먼저 해결**: 이미 등록 가능한 투자·체중·완독 목표가 실제로 달성률을 보여 주게 하는 것이 새 지표 추가보다 효과가 큽니다.
2. **A그룹에서 2~3개 추가**: 체지방률, 운동한 날 수, 시청 편수를 추천합니다. 모두 새 원본 필드 없이 Data Hub 어댑터만 추가하면 됩니다.
3. B그룹은 기간 규칙을 결정한 뒤 진행합니다.
4. C그룹은 원본 저장 구조를 바꿔야 하므로 데이터 보존 원칙상 별도 승인과 설계가 필요합니다.

- 목록에 없는 생활 영역(수면, 독서 시간, 저축률 등)이 있다면 알려 주세요. 원본 기록 자체가 없는 분야는 입력 화면부터 필요합니다.

## 5. 확인하지 않은 것

- 각 분야에 실제 기록이 얼마나 있는지(데이터 열람 안 함)
- 다른 탭에서 진행 중인 목표 초안·삭제 기능의 미병합 코드
- 모바일 화면에서의 입력 편의
