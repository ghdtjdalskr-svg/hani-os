# HANI OS · 통합 검수 개선 구현 현황

성민 대표님 검토용 · 2026-10-05

Claude·Gemini 통합 최종 보고서의 채택 항목을 개발 브랜치에 구현했습니다. 운영 배포는 하지 않았습니다. 보호 원본 키와 내부 데이터 버전, Cloud schema는 유지했습니다. 실제 생활 기록을 테스트에 사용하거나 수정하지 않았습니다.

## 이번에 달라진 동작

| 항목 | 구현 결과 | 확인 상태 |
|---|---|---|
| D01 · 손상 원본 | 읽기 오류를 신규 사용자로 처리하지 않고 저장·Cloud 반영을 잠급니다. 정확한 원문 보존과 별도 사본의 재읽기를 확인하며 빈 화면을 원본으로 내보내지 않습니다. | 가상 데이터 검증 완료 |

| D10 · 투자 표 | 모바일 가로 이동 안내와 키보드로 이동 가능한 표 영역을 추가했습니다. 실제 종합 투자 화면으로 옮겨지는 DOM에서 검사했습니다. | 모바일 힌트·키보드 가로 스크롤·아린 검토 완료 |
| D11 · 기록 정합성 | 기기명을 현재 표시 버전에 연결하고 stability 파일에 캐시 버전을 붙였습니다. 근거가 확인된 v168 운영 상태와 v175 Pages 기준을 구분하고 오래된 QA 문서는 현재 후보 검증과 구분해 보존하고 중앙 인덱스에 시점 안내를 붙였습니다. | 실행 기기명·근거 문서·syntax 확인 |

D08 저장 안내와 D09 팀 분리는 이미 구현돼 있어 이번에 다시 만들지 않았습니다. 개발 기록 전체를 자동으로 운영 완료로 승격하거나 사용하지 않는다고 추정한 파일을 삭제하지 않았습니다.

## 백업이 계속 쌓일 때

새 원본 전체를 저장하고 재읽기에 성공한 다음에만 **이 보관소의 오래된 확인 완료 사본**을 정리합니다. 최신 사본 확인이 실패하면 이전 사본을 정리하지 않습니다. 정리가 실패하면 3개를 초과해 보존하고 보류 안내를 표시합니다. 기존 Local 안전 사본은 유지합니다.

별도 보관소가 실패하면 기존 안전 사본 1개를 재읽기로 확인한 경우에만 제한적으로 진행하고, 이력이 늘지 않았음을 알립니다. 두 방식 모두 실패하면 Cloud 반영을 멈춥니다. 브라우저의 사이트 데이터 삭제는 이 보관소도 삭제하므로 파일 다운로드는 계속 필요합니다.

백업을 기다리는 중 새 Local 기록이 입력되거나 다른 탭에서 복원 보류가 바뀌면 새 원본을 유지하며 자동 처리를 중단합니다. 이미 전송된 요청은 서버에서 처리될 수 있으므로, 응답 후에는 Local을 덮거나 새 보류를 해제하지 않습니다. 다음 Cloud 비교·기준본 확인이 필요합니다.

## 미리보기와 운영 반영 경계

[가상 데이터 미리보기](http://127.0.0.1:8814/.preview/quality.html)는 저장소를 메모리로 대체하고 외부 연결을 차단한 로컬 전용 파일입니다. 운영 파일과 패키지에 포함하지 않습니다. 현재 미리보기는 최신 후보를 사용하며, 개발 후보는 v2.9.178 기능을 보존하고 v2.9.179로 준비했습니다.

최신 main 확인과 후보 표시 버전 증가는 완료했고, 동결한 후보의 패키지·실행 증거를 준비 중입니다. 운영 최종 HINA Gate·대표 승인·Pages/read-back은 아직 수행하지 않았습니다. Pre-QA dry run은 저장 변경/보호 키/이벤트 검토를 BLOCKED로 표시하며, 로컬 Preview·화면 증거도 배포 허용 경로 밖입니다. 성민 대표님의 별도 승인으로 강화 게이트를 개발했으며, 정확한 승인 정책·검증 증거가 없으면 기본 차단을 유지합니다. [강화 게이트 절차](protected-write-gate-runbook.md)를 확인하세요.

운영 반영 전 서버의 `HANI_OWNER_USER_ID`를 검증·설정해야 합니다. 값이 없는 상태로 두 Function을 먼저 배포하면 대표 계정도 거부됩니다. 현재 실제 운영 Function에는 이 제한이 아직 반영되지 않았습니다. 가입 정책 변경·계정 삭제는 이번 범위에 포함하지 않습니다. 서버 배포 순서는 [D02 운영 준비 문서](quality-server-authorization.md)에 기록했습니다.
