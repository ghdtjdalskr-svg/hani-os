## 제안의 중심

성민 대표님이 밤에 잠깐 들어왔을 때, 방금 남긴 작은 기록을 직원들이 반갑게 받아 주는 앱을 제안한다. 새 숙제나 수집 의무를 만들지 않는다. **우선 구현 후보는 ‘윤슬의 완독 책갈피’, ‘히나의 수고했어요’, ‘마일스톤 앙코르’**다. 기존 화면 안에서 끝나며, 새 저장·Cloud·AI 호출 없이 만들 수 있고 `hani-office-live.js`와 직접 겹치지 않는다.

이 보고서의 대사는 제안 문구이며 실제 성민 대표님의 기록·감상·성과가 아니다. 사용 성향은 작업 파일에서 제공한 내용만 사용했다. 코드와 개발 이력은 기능의 존재와 경계를 확인하는 데만 썼으며, 개인 기록 원문은 옮기지 않았다. 앱 안의 호칭은 ‘회장님’, 이 작업 보고의 호칭은 ‘성민 대표님’으로 구분한다.

### 공통 설계 조건

- 밤·짧은 휴식·Galaxy 화면을 기준으로 한 장면은 5~15초 안에 이해하게 한다. 기본은 짧은 한 줄, 자세한 반응은 직접 펼친다. 자동 모달·소리·진동·푸시 없음.
- 칭찬은 **기록에 확인된 행동**에 붙인다. 책의 교훈, 운동 강도, 감정, 건강 개선, 실제 투자 성과는 추측하지 않는다. 기록 없음은 실패·태만·0점이 아니다.
- 추가 입력 0개를 기본으로 한다. 점수 경쟁, 연속 출석, 친밀도 하락, ‘직원이 기다린다’는 죄책감, 다음 화를 열기 위한 할당량을 넣지 않는다.
- 제안 기능의 추가 쓰기는 0이다. `localStorage`, `sessionStorage`, IndexedDB, 쿠키, `state` 필드에 새 상태를 저장하지 않는다. 페이지 메모리의 펼침·타이머는 허용하지만 새로고침하면 잊는다. ‘하루 한 번 영구 보장’이라고 표현하지 않는다.
- 모든 반응은 준비된 문구와 기존 기록의 읽기 전용 투영이다. 기존 AI 생성·댓글 발행·Cloud 저장 기능을 호출해 반응을 만드는 방식은 제외한다. 기존 앱 자체의 네트워크·저장 동작과 제안 기능으로 추가되는 동작을 구분한다.
- 금액·수익률·보유 종목·소비액·재무 목표 달성 여부를 재미의 재료로 쓰지 않는다. 금융 화면에서는 문서 날짜·분류·이미 저장된 상태만 중립적으로 안내한다. 매수·매도·절약·예산 조정 조언 없음.
- 개인화한 내용은 인증된 앱 안에만 표시한다. 새 공유·전송·분석 로그·외부 이미지 URL·AI 프롬프트에 기록을 넣지 않는다. 기존 인쇄/PDF/PNG/보고서 캡처에도 **새 개인화 슬롯은 제외**한다.
- 기존 renderer·위임 handler·말풍선 owner를 확장한다. 공통 MutationObserver, 저장 함수 가로채기, 별도 사무실 loop는 만들지 않는다. `prefers-reduced-motion`에서는 정적 문구만 제공한다.

### 공통 연결을 만들 때의 경계

1. **첫 세 작업에는 공통 연결 엔진을 만들지 않는다.** 각각 원래 화면의 검증된 항목만 읽는다. 여러 화면 연결은 F14/F18 또는 연속극을 실제로 선택한 뒤 별도 NORMAL 작업으로 진행한다.
2. 후속 공통 투영은 기존 `hani-ilbo.js` 안의 순수 함수로 소유시키는 안을 제안한다. 예: 새 `funFacts(source, period, now)` → `{kind, sourceKey, day, route, certainty}`. **이 API는 현재 존재하지 않는 제안**이다. 기존 `compute` 결과 전체나 `HaniBoard.realEvents` 전체를 재사용하지 않는다. 금융·건강 수치·자유 텍스트가 새 함수 반환값에 들어오지 않도록 허용 목록으로 구성한다.
3. 인증된 런타임의 `state`/기존 검증된 읽기 API만 사용한다. 저장소를 따로 다시 읽거나 숨겨진 기록을 복구하지 않는다. 데이터가 아직 준비되지 않았으면 일반 대사만 보인다. 금융 값은 읽지 않으며 건강은 유효한 기록 존재만 전달한다.
4. 기존 화면 진입/렌더 시 계산한다. 사무실은 기존 update에서 주차·데이터 참조 변화가 있을 때만 작은 메모리 캐시를 갱신한다. 매 프레임 전체 기록을 스캔하지 않는다. 객체/내용 갱신 신호가 불명확하면 화면 진입마다 재계산하는 단순한 방법을 택한다.
5. 같은 입력이면 같은 대사를 사용한다. 일자·원래 ID·장면 ID에 따른 결정적 선택으로 새로고침마다 화자가 바뀌는 혼란을 줄인다. 읽음 표시·반응 횟수·기사 발행 ID를 저장하지 않는다.
6. 수정·삭제 후에는 현재 원본에서 다시 계산한다. 과거 일보 개인 별지도 재계산되므로 ‘발행 당시 고정 기사’라고 표현하지 않는다. 영구 스냅샷·기기 간 읽음·비밀 대화 기억은 **성민 대표님의 별도 저장 승인 필요**다.
7. 라운지 연결은 실제 글/댓글이 아닌 접힌 화면 코너다. 기존 `generateDaily`, `materialize`, `persist`, `savePost`, `saveComment`, `requestLoungeAI`를 호출하지 않는다. 반응·투표·알림 건수에도 넣지 않는다.
8. 일보 별지·연속극 개인화 패널에는 인쇄 제외 스타일을 적용하고, 현재 화면을 캡처하는 앱 내 출력 경로에서도 제외한다. 원래 기사·저장된 사용자 코멘트의 기존 출력 정책은 이 작업에서 바꾸지 않는다.

## 4. 몇 주씩 이어지는 이야기 세 가지

### 공통 진행 규칙

4주 시즌은 ‘월요일 시작 KST 주차’와 코드에 정한 시즌 시작 주를 기준으로 진행한다. 시작 주는 콘텐츠 상수이며 사용자 데이터가 아니다. **본편은 주차만으로 진행하고, 활동은 짧은 추가 장면을 바꾼다.** 활동이 없어도 다음 편·완결을 볼 수 있다. 놓친 화는 ‘지난 이야기’에서 읽는다. 화면은 한 번에 한 장면만 보여 주며 자동 이동·다음 화 알림은 없다.

활동에 따른 장면은 해당 주 원본 기록에서 매번 재구성한다. 지난주 선택 분기에 이번 주 사건의 필수 원인을 걸지 않는다. 따라서 기록을 정정해도 이야기의 결말이 모순되지 않는다. 원본이 삭제되면 그 주의 개인 장면은 일반 장면으로 돌아간다. ‘그때의 분기를 영구히 기억하는 연재’를 원하면 별도 저장 승인이 필요하다.

정적 본편은 창작 사내극임을 코너 제목에서 알 수 있게 하고, 실제 기록을 언급하는 짧은 별도 줄에는 ‘기록 기준’과 날짜를 붙인다. 개인 기록을 정적 `data/` 콘텐츠 파일이나 공용 library에 채워 넣지 않는다.

민지가 사내 영화제를 열려는데 제목부터 너무 거창하다. 아린은 포스터의 글자를 줄이고, 히나는 엔딩 자막의 오탈자를 찾고, 수연은 어디서든 여행 다큐를 상영하려 한다. 회장님의 기록은 상영 작품이나 평가 점수가 아니라 주간 개인 별지의 짧은 크레딧이다.

## 6. 상위 세 가지 개발 명세

공통 완료 조건: 코드 구현 후 해당 기능의 targeted regression과 실제 Preview를 확인한다. 아래 테스트 목록은 **향후 구현 시 실행할 계획**이며 이번 조사에서 실행한 결과가 아니다. 독립 아린/HINA 리뷰를 이번 보고서가 대신하지 않는다.

### 명세 A — F03 윤슬의 완독 책갈피

**목적·사용 흐름**

서재의 완독 카드에서 한 번 탭해 윤슬의 짧은 반응을 읽는다. 새 입력/후기 없이 이미 읽은 책을 다시 보러 올 이유를 만든다. 기존 `saveBook`, 분류 전환, `HaniMotion.completion`은 그대로 둔다.

**범위·소유 경로**

- `hani-main.js`의 `bookCard(b)`가 markup을 소유한다. `renderReading()`의 기존 페이지별 카드 렌더 경로를 사용한다.
- CSS는 `hani-design-system.css`의 `#reading` 아래로 제한. `index.html`의 script/캐시/버전 변경 없음.
- 제안 helper `bookThanksEligible(book, allBooks, todayKst)`는 순수 읽기 함수. 현재 존재하는 API가 아니며 구현 시 `bookCard` 근처에 둔다. 렌더러에서 계산한 적격 여부를 카드에 전달해 같은 배열을 카드마다 재집계하지 않는다.

**데이터 계약**

`status === 'read'`, 고유하고 비어 있지 않은 `id`, 유효한 완독일≤KST 오늘이 모두 필요하다. `completedDate`와 호환 `readDate`가 모두 있으면 둘 다 유효하고 같아야 한다. `activityDate`의 날짜 검증 규칙을 재사용하되 누락된 날짜를 오늘로 채우지 않는다. `createdAt`/`updatedAt`을 완독일로 바꾸지 않는다. 동일 ID 충돌·날짜 누락·미래 날짜는 책갈피를 숨긴다. 기존 카드와 원본은 그대로 보인다.

**화면**

카드의 기존 제목/후기 아래, 수정·삭제 action과 분리해 native `details`를 넣는다.

```text
기존 책 제목 · 기존 완독일
▸ 윤슬의 책갈피
  윤슬  “책 한 권 끝까지 읽으셨네요.
         책갈피는 잠깐 쉬겠습니다!”
[기존 분류 전환] [수정] [삭제]
```

기본 닫힘. 펼침 한 번에 두 줄 이내. 인물 이미지는 필수가 아니며 이름은 roster의 `yoonseul`에서 읽는다. 인물이 없으면 이름 없는 ‘완독 책갈피’로 표시한다. 직접 템플릿에 사용자의 제목·후기·저자·평점을 삽입하지 않는다. 고정 문구 4개를 `id`의 안정된 해시로 선택하되 동일 기록은 재렌더해도 같은 문구를 사용한다. 문구 예: “완독 소식, 반가워요.”, “끝까지 읽은 한 권에 조용히 박수.”, “책갈피는 잠깐 쉬겠습니다.”, “회장님 서재에 한 장면이 남았네요.”

**이벤트·수명**

native `details`라 새 click listener가 필요 없다. 펼침 상태를 `state.ui`나 저장소에 넣지 않는다. 검색·정렬·페이지 변경으로 카드가 재렌더되면 접힐 수 있으며 의도된 동작이다. 기존 저장/분류 전환 성공 후 render 경로로 표시되지만 성공 toast를 하나 더 띄우지 않는다. 완독 상태를 되돌리면 책갈피도 사라진다.

**접근성·안전**

summary 터치 영역 최소 44px, Enter/Space 기본 동작, 밝음/어두움 대비 4.5:1 이상. 긴 제목은 기존 wrap, 텍스트 200%에서 가로 넘침 없음. 애니메이션·음향 없음. 새 개인화 구역은 인쇄 제외. 기록 문자열은 기존 escape 경로로만 출력하며 이 기능은 `save`, `commit`, `agentApi`, storage API를 호출하지 않는다.

**인수 기준과 테스트 계획**

1. 정상 완독·호환 날짜·미래일·날짜 충돌·날짜 없음·wish·중복 ID를 fixture로 넣어 적격성 검사. 원본 객체를 deep-freeze하고 호출해 mutation이 없는지 확인.
2. 실제 `bookCard`/`renderReading`에 합성 도서를 넣고 책갈피가 해당 카드에만 생기는지 확인. 제목에 HTML 문자가 있어도 실행되지 않아야 한다.
3. 펼침/접기/키보드/페이지 변경 동안 추가 storage·Cloud·AI 요청 0. 앱의 기존 부수 요청은 차단한 fixture에서 비교한다.
4. 수정·삭제·분류 전환 handler와 `saveBook` 성공/실패 경로가 바뀌지 않았는지 확인. 저장 실패 시 ‘새 완독’ 효과를 만들지 않음.
5. 현재 있는 `scripts/hani-simplify-218.test.cjs`와 `scripts/hani-fix-208-ui.test.mjs`의 관련 독서/완료 효과 회귀를 확인하고, 적격성·화면 검사는 별도 최소 테스트로 추가. 실행 환경/인자는 기존 파일 지침대로 준비.
6. 360/390/412px와 1440px, light/dark, 긴 제목·이미지 없음·200% 글자 Preview. 브라우저 불가 시 UI 미검증으로 남김.

**되돌리기:** 새 책갈피 markup/helper·해당 CSS만 제거한다. 데이터 복구/마이그레이션 없음. 예상 S, `hani-office-live.js` 수정 없음.

### 명세 B — F05 히나의 수고했어요

**목적·사용 흐름**

퀴즈를 마친 회장님이 점수와 별개로 완료 행동을 인정받는다. 현재 `submitExam → gradeQuiz → renderLearning → renderQuizDetail` 흐름과 약 1.6초 채점 완료 도장은 유지한다. 새 쪽지는 **결과 상세 화면에 남는 요소**다.

```text
기존 채점 완료 · 점수 / 회차 / 문항 수
▸ 히나의 마무리 한마디
  한 세트 마무리! 빨간 펜도 잠깐 뚜껑 닫을게요.

```

**이벤트·오류 처리**

native 펼침만 사용하므로 추가 AI 요청이 없다. 쪽지에서 ‘다음 시험’, ‘계속 공부’ 버튼을 만들지 않는다. 기존 화면 재진입 때 같은 문구를 보여 줄 수 있지만 새 댓글/보상 지급처럼 표현하지 않는다. 채점 저장이 실패하면 기존 rollback·오류 안내가 우선이며 이 쪽지는 나타나지 않는다. 재채점으로 점수가 바뀌어도 문구는 유지된다. 캐릭터 이름 조회 실패 시 ‘마무리 한마디’로 표시하고 결과 화면은 계속 동작한다.

**인수 기준과 테스트 계획**

3. 반복 펼침·복귀·문항 첨삭 복사·이의제기에서 기존 이벤트 수 불변, 추가 저장/AI 0. `gradeQuiz`와 `persistQuizAnswer` 원문 보존을 확인한다.

### 명세 C — F12 마일스톤 앙코르

**목적·사용 흐름**

이미 남겨 둔 기쁜 순간을 한 번 더 축하받는다. 상세 카드의 저장된 직원 코멘트와 새 화면 반응을 명확히 나눈다. 회장님이 버튼을 누를 때만 1초 안팎의 작은 박수와 한 줄 문구를 보여 준다.

**범위·소유 경로**

- `hani-milestones.js`의 `detail`이 `data-ms-encore` 버튼과 하나의 status 슬롯을 만든다. 현재 `openDetail`이 만든 dialog 안에서 동작한다.
- `start()`의 기존 `host.addEventListener('click', ...)` 분기 한 곳에서 처리한다. 별도 document listener·dialog·renderer 없음.
- `hani-milestones.css`에 `#milestones` 아래 style. 기존 카드 시트·등급·별·썸네일·저장/삭제/폼은 그대로.

**대상 판정**

현재 `merged().items`에서 찾은 유효한 record이며 `!isPending(m)`, 유효한 날짜≤KST 오늘, `category`가 `FINANCE`/`INVESTMENT`가 아니어야 한다. 기존 카드의 seed 여부는 상세 재감상을 막지 않지만 **새로운 사용자 성취라고 알리지 않는다**. 모든 금액·건강 수치·title·summary·metrics·자유 코멘트를 새 대사 입력에서 제외한다. 일반 카테고리 제목에 금융 내용이 들어 있더라도 ‘기록을 돌아보는 행위’에만 반응하며 성과/수익/몸 상태를 평가하지 않는다.

대기/미래/손상/금융 기록에는 앙코르 버튼을 숨긴다. 기존 상세 내용·수정 버튼은 유지한다. 기존 `PENDING_IDS`를 해제하거나 자동 등록하지 않는다.

**대사·UI**

버튼은 ‘한 번 더 박수’. 바로 아래 고정 슬롯에 하니의 “회장님이 남겨 둔 순간, 다시 함께 기뻐해요.”를 표시한다. 저장된 `Agent Comment`와 별도 ‘앙코르’ 영역이다. 기본안은 하니 고정 화자이며 해당 roster가 없으면 이름 없는 문구로 표시한다. 직원들이 실제로 이 기록을 읽거나 새 댓글을 작성했다고 표현하지 않는다.

```text
기존 마일스톤 제목·날짜·카드
[한 번 더 박수]
하니 · 회장님이 남겨 둔 순간, 다시 함께 기뻐해요.
기존 전후 지표 / 저장된 Agent Comment / 수정·삭제
```

**상태·연타·종료**

- 표시 문구·애니메이션 token·timer는 페이지 메모리/DOM에만 있다. `state.milestones`, `agentComments`, 좋아요 수에 쓰지 않는다.
- 클릭 직전 현재 `ui.detail`과 대상 ID의 적격성을 재확인한다. 재생 중 연타는 무시한다. 약 1초 후 버튼을 다시 사용할 수 있으며 문구는 상세를 닫을 때까지 남는다.
- 작은 👏 또는 기존 CSS 강조 1회만 표시한다. 별도 자산 다운로드/음향/진동/화면 전체 confetti 없음. reduced-motion에서는 즉시 정적 문구만 표시한다.
- `back()`·닫기·다른 record 열기·뷰 변경 시 timer/token을 무효화한다. 이전 상세의 늦은 timer가 새 상세의 버튼이나 슬롯을 바꾸면 안 된다. 해제 시 stale DOM 참조도 버린다.
- `role=status` 또는 `aria-live=polite` 슬롯 하나로 한 번 읽는다. 버튼 focus는 유지하며 새 modal이나 focus 이동을 만들지 않는다. 새 개인화 영역은 인쇄/앱 출력 제외.

**인수 기준과 테스트 계획**

1. 비금융 달성/대기 ID/미래일/금융/손상/seed·저장 override 조합을 검사한다. 날짜가 있다고 대기를 달성으로 바꾸지 않음.
2. 실제 기존 click delegation을 통해 단일 반응이 나오는지 확인. 연타·닫기·다른 카드 즉시 열기·화면 이동의 fake timer 검사로 늦은 갱신 차단 확인.
3. 재렌더·새로고침 때 박수 누적 0. 새 버튼에서 `persist`, `save`, Cloud·AI 호출 0, `state.milestones` deep-equal 유지. 기존 수정/삭제 실패 복원 경로 불변.
